# 音频频谱模式 · 设计文档

> 状态：**设计已定**（下述决策已在对话中逐条锁定）
> 日期：2026-10-14
> 关联：仪表盘壳体重构见 `2026-10-14-dashboard-chrome-redesign-design.md`，排在本功能**之后**，两份 spec 分开写、分开审。

## 0. 已锁定的决策

| 项 | 决定 |
|---|---|
| 音频来源 | 默认播放设备**回环**（扬声器/耳机正在播放的系统音） |
| 采集库 | `soundcard`（**实测 sounddevice 0.5.6 的 `WasapiSettings` 不接受 `loopback`**，改用 soundcard；纯 Python + cffi，免编译） |
| 模式形态 | **全屏接管**：保留顶栏，指标卡片让位 |
| 频谱风格 | 三种：① LED 点阵柱（默认）· ④ 峰值保持 · ⑤ 镜像渐变柱 |
| 频段 | **24 段对数分布 40Hz–16kHz** |
| 包络 | 快攻 **0.05s** / 慢放 **0.25s**；峰值保持 **0.8s 后下落**，下落斜率与释放同速 |
| 瓦数开关 | **一个**开关同时管 CPU/GPU 卡片内的 `~36 W`；功率卡 PWR·EST **不受影响** |
| 视觉语言 | **母带仪表**：共用基线导轨 + 频率刻度 + dB 网格 + 接近满量程转琥珀 |

## 1. 数据层（采集）

- `soundcard` 抓**默认播放设备**的回环通道：`sc.get_microphone(id=str(sc.default_speaker().name), include_loopback=True)`。面板可填设备名覆盖（配置项 `spectrum_device`，留空＝默认播放设备）。
- 采样 48 kHz，每次取 1024 帧（≈21ms）写入**环形缓冲**；渲染主循环非阻塞地取"最新完整块"，取不到就复用上一块（**绝不阻塞渲染**）。
- 依赖按**惰性导入**：`soundcard` 不在时程序照常运行，只是频谱模式不可用。
- `requirements.txt` 增加 `soundcard`；`build.py` 增加 `--collect-all soundcard`（把 soundcard 与 cffi 一并打进包）。
- **降级链**：无依赖 → 无回环设备 → 打开失败 → 采集异常，逐级降级为**静默基线**（一条 0 电平的平线）；**不崩、不刷日志、不重连风暴**（沿用项目"找不到就留空不报错"的既有约定）。
- **降级提示落在哪儿（实现期修正）**：原计划是"顶栏挂一个小提示点"，实现时发现顶栏已经没有空位 —— 主板型号、网速读数、时钟、电源指示灯（`x = 301..307`）把 304px 占满了，另挂一个点会与电源指示灯重叠。改为**让电源指示灯本身承载故障**：正常时绿色脉冲，频谱模式下采集不可用时转琥珀脉冲。仪器只有一盏灯时，灯变色正是仪表该有的语言。
- 已知风险：WASAPI 回环抓不到**独占模式**播放的流（此时读数为静默）；不试图绕过，走降级提示。

## 2. 频域层

- 1024 点 FFT + 汉宁窗；只取实信号的前半谱。
- 频段切分：24 段**对数**分布 40Hz–16kHz，每段取**带内峰值**（而非均值，瞬态更跟手）。
- 归一：幅度转 dB，以 −60dB 为底映射到 0..1。
- 包络：一阶跟随，攻击 0.05s / 释放 0.25s，按帧时长步进（与帧率解耦）。
- 峰值保持：记录每段最大值，**0.8s 后**按释放同速下落；与包络共用同一支时钟。

## 3. 渲染层

**固定几何**（三种风格共用）

- 频谱带：`x = 8..312`（304px），24 段，pitch ＝ 304/24 ≈ 12.667px；柱宽 8px（① 用 10px 的 LED 格）。
- 带高：`y = 33..153`（120px ＝ **12 行 × 10px**，正好压在脏矩形网格上）。
- 中线（⑤ 用）：`y = 93`；基线导轨：`y = 152`；刻度行：`y ≈ 154..165`。
- **与壳体家具的关系**：预览草图里曾暴露"表壳底角螺钉与刻度行同高"的冲突，实现时确认了 —— 真机 quartz 面在频谱模式下由**整块面板表壳**承担（四边导轨 + 四角螺钉，新增 `_panel_case()`；原来只有每张卡片各有表壳），刻度落在 `x≈52..293`，天然避开四角的螺钉，**不需要额外内缩**。

**① LED 点阵柱（A 档 · 默认）**

- 每格 10px 见方，亮/灭两级：灭格用 **13% 白幽灵底**（与 quartz 面七段数码的幽灵笔画同一手法）；亮格**实心**，最高一格混白 42% 提亮。
- 幽灵格**烘焙进静态层**：首帧一次，之后不产生任何带宽；只有"跨格"的格子产生脏区。

**④ 峰值保持（A 档）**

- 柱体**平色实心**（高度变化只脏它跨过的行）；柱高**量化到 2px**。
- 帽：3px 高，跟随峰值保持值；**段位 > 0.88 时转琥珀**（与仪表盘既有负载告警同一套语言）。
- dB 网格线（−6/−12/−18 等）烘焙进静态层。

**⑤ 镜像渐变柱（A\* 档）**

- 以中线上下镜像，柱内竖直渐变（外端亮、中心暗），外端**圆头柱帽**。
- 柱高**量化到 2px**；渐变条按量化高度**预烘焙并缓存**（每种高度一张），因此未跨越台阶的柱子整帧零成本。
- 中缝加 1px 发丝线。

**壳体适配**

- `glass` 面：频谱直接落在背景上（裸背景即画布）。
- `quartz` 面：频谱落在**表盘**上（复用现有 `_dial()`），顶栏保留金属铭牌。
- 两面的顶栏在频谱模式下**照常显示**（主机/主板、网速、时钟、绿点）。

**模式切换的开销**：切换模式会重烘焙静态层，首帧几乎全屏改变 → `dirty_rects` 必然超过整帧阈值，自动走整帧发送，**无需额外代码**。

## 4. 模式与配置

新增配置项（`config.py`）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `mode` | `"dash"` | `"dash"` / `"spectrum"` |
| `spectrum_style` | `"led"` | `"led"` / `"peak"` / `"mirror"` |
| `spectrum_device` | `""` | 留空＝默认播放设备 |
| `show_watt` | `True` | CPU/GPU 卡片内那行 `~36 W` 的显隐（**功率卡不受影响**） |

- **`_look_sig()`**：`mode` 与 `spectrum_style` 参与静态烘焙，**必须进 sig**；`show_watt` 是动态文本，**不进 sig**（与 `show_net` 同理）。
- **面板 SCHEMA**：沿用现有 5 组结构 —— 「画面」组新增「显示模式」子区（显示模式 / 频谱风格 / 采集设备）；「显示调节」子区加一行「卡片内瓦数」开关。
- 三处齐全：`Config` 字段 + `update_from()` 白名单（`fields()` 自动覆盖）+ SCHEMA 行。

## 5. 带宽与验证

**目标**：频谱模式 30fps 下 **≤ 300 KiB/s**（链路实测上限约 800 KiB/s，仪表盘自身约 150 KiB/s）。

**实测结果（2026-10-14）**

合成最坏情况（`--demo` 全幅驱动 24 段，按 30fps 折算）：

| 组合 | 渲染耗时 | 每帧脏区 | 30fps 折算 |
|---|---|---|---|
| led | 3.3–3.5 ms | 12.3 KiB | **368 KiB/s** |
| peak | 2.6–3.4 ms | 21.9 KiB | **658 KiB/s** |
| mirror | 3.5–4.3 ms | 33.6 KiB | **1008 KiB/s** |
| （仪表盘基线） | 24.6–32.5 ms | 14.7–16.2 KiB | 441–487 KiB/s |

实机（真链路 + 合成宽带音源驱动全部 24 段；测时机器 CPU 已被其它程序占到 87%，fps 偏悲观）：

| 组合 | fps | KiB/s |
|---|---|---|
| glass/dash | 14.0 | 265.9 |
| quartz/dash | 19.1 | 297.8 |
| glass/led | 49.9 | 320.5 |
| quartz/led | 46.8 | 298.0 |
| glass/peak | 50.4 | 405.5 |
| quartz/peak | 47.7 | 385.1 |
| glass/mirror | 15.2 | 475.9 |
| quartz/mirror | 14.1 | 445.9 |

结论：**渲染耗时三种风格都远在 16.7ms 预算内**；①④ 在实机上稳定 47–50fps，达到"45+"要求。⑤ 的每帧脏区是 ① 的 2.5 倍 —— 它的渐变条按柱高**拉伸**（换高度＝整根柱子重画），所以最坏情况下折算带宽会顶到链路上限，30fps 保不住。这是 ⑤ 的**固有代价**：要"任何高度都保持亮端"就必须让渐变随高度缩放，也就必须整柱重画。留作待决项（见 §7）。

**验证清单**

1. `python -m compileall -q hubmon`
2. 合成频谱驱动（`--demo`）跑 `style_cost.py` / `style_link.py`，量三种风格每帧**脏区字节数**与**渲染耗时**。
3. 实机跑 60s：读日志里的实测 fps 与 KiB/s，确认 ≤300 KiB/s 且帧率仍有 45+。
4. 6 组全测：3 风格 × 2 壳体。
5. 降级测试：屏蔽 `soundcard` 导入 → 确认程序照常启动、频谱退化为静默基线、顶栏有提示、无异常风暴。
6. 三种风格的断言脚本（`spec_analyser` / `panel_spec` / `spec_bake` / `spec_led` / `spec_peak` / `spec_mirror` / `spec_wire` / `spec_watt` / `spec_fallback`）全绿。

## 6. 明确不做（YAGNI）

- 不做 **C 档**风格（瀑布谱 / 环形雷达谱）—— 留作后续扩展。
- 不做麦克风输入、不做多设备混音、不做与系统音量联动。
- **不改仪表盘卡片几何与壳体** —— 那属于工作流 B，独立 spec 独立周期。
- 不做频谱的"峰值写回配置"或历史记录。

## 7. 待确认与风险

1. ~~采集库会不会没有回环能力~~ **已实测（任务 1）**：`sounddevice` 0.5.6 无回环，改 `soundcard` 后通过（枚举 9 个回环端点、默认扬声器为 `SteelSeries Sonar - Gaming`、录到 9600×2 帧真实数据）。
2. ~~打包成 exe 后能否枚举到回环设备~~ **已实测（任务 10）**：源码可用、**冻结包不可用**，`CoCreateInstance` 返回 `0x800401f0`（`CO_E_NOTINITIALIZED`）。根因：`soundcard` 的 COM 公寓在**导入它的那个线程**上建立（`_com = _COMLibrary()` 是模块级单例），而采集线程是后起的新线程，冻结包里没有隐式 MTA 兜底，于是那一步没有公寓可用。修法：采集线程自己在 `_run()` 开头 `CoInitializeEx(NULL, COINIT_MULTITHREADED)`。修后冻结 exe 实测 `spec_state=ok`、57fps。**这条不随会话消失 —— 任何"在子线程里用 soundcard/COM"的改动都要记得它。**
3. 24 段在 304px 上 pitch 非整数（12.667），柱宽取整会有 ±1px 漂移 —— 接受轻微不等宽，或用 304/24 的取整表固定下来。
4. 采集线程与 USB 主线程的优先级：采集线程不得拖慢渲染（已实测：频谱模式渲染 2.6–4.3 ms/帧，远比仪表盘轻，fps 不掉）。
5. **⑤ 镜像渐变柱的带宽（待决）**：整柱随高度缩放 → 最坏情况折算 ~1 MiB/s，超出链路上限。两个方向，二选一或都不选：(a) 渐变改按**到中线的绝对距离**取色（柱子不随高度缩放），只有跨过的行产生脏区，代价是"低电平的柱子整体偏暗"；(b) 保持现在的观感，接受它在最响的音乐下约 24fps、其余情况正常。**未与用户确认前不动它。**
