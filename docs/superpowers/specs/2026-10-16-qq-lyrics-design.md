# 频谱模式歌词背景 — 设计文档

日期：2026-10-16
状态：待用户审阅

## 1. 目标

在**频谱模式**下，于频谱上部**叠加一行半透明歌词**，跟随 QQ 音乐当前播放**逐句**显示：

- 歌词来源：QQ 音乐当前播放曲目（歌名/歌手由系统媒体会话 SMTC 读取）。
- 换句时机：**跟唱**——按播放进度 + 歌词时间轴定位当前句；暂停则整块隐去。
- 两种出场动效：**渐隐**、**几何重构**，并支持**轮换**（面板三选一）。

非频谱模式、歌词功能关闭、或拿不到歌词时，本条链路完全空转，不影响原有画面。

## 2. 可行性结论（已在本机实测，非推测）

| 环节 | 结论 | 证据 |
|---|---|---|
| SMTC 读取 QQ 音乐元数据 | ✅ 可用 | `aumid=QQMusic.exe`，`title/artist/album` 正常 |
| SMTC 读取播放进度 | ✅ 可用（**前置条件见下**） | 轮询 12s：`pos` 从 14.6s 连续推进到 25.7s，`end=4:32`，`last_updated` 持续刷新 |
| 歌词检索（QQ 音乐接口） | ✅ 可用 | `musicu.fcg` 搜 `粤语残片 陈奕迅` → 得到 `mid` |
| 歌词正文（带时间轴） | ✅ 可用 | `GetPlayLyricInfo` 返回 base64 LRC，解出 **54 行带 `[mm:ss.xx]` 时间戳**的歌词 |

### 关键前置条件（必须写进文档与面板提示）

**QQ 音乐必须在「设置 → 通用设置 → 通知 → 显示系统媒体传输控件 (SMTC)」开启，并且开启后【完全退出再重启】QQ 音乐，timeline 才会上报。**

实测：开关已开但进程未重启时，`pos/end` 恒为 0、`last_updated=1601-01-01`；重启后立刻正常。版本要求 ≥ 21.10.2962（本机 22.70）。

### 已知局限

- QQ 音乐**手动拖动进度条 seek 之后**，SMTC 进度可能短暂不更新（Lyricify 文档记载的已知问题），歌词会短暂失准，下一句/下一首后恢复。
- 拿不到进度时退化为本地时钟估算（见 §5）。

## 3. 已确认的决策（来自需求澄清）

| 项 | 决策 |
|---|---|
| 歌词获取 | QQ 音乐接口优先，第三方 LRC 接口兜底 |
| 媒体接入 | 模块化 `winrt`（非 `winsdk`） |
| 显示位置 | **悬浮在频谱上部**，半透明压在柱子上 |
| 歌词不透明度 | 可调，默认 0.55 |
| 动效 | 面板可选：渐隐 / 几何重构 / 轮换，默认轮换 |
| 几何重构语义 | 每个字切成小块，从散乱位置飞拢重组成整句 |
| 换句 | 跟唱（按时间轴） |
| 暂停 / 无歌 | 歌词整块隐去 |
| 断网 / 匹配不到 | 安静不显示歌词层，频谱照常 |

## 4. 架构

新增模块 `hubmon/lyrics.py`，三个互相解耦的单元：

### 4.1 `MediaWatcher`
后台线程，负责读 SMTC，约 **0.7s** 轮询一次，产出快照：

```
{title, artist, album, status(playing/paused), position_s, duration_s, song_id}
```

- `song_id`：从 SMTC 的 `genres` 列表里解析形如 **`QQ-<数字>`** 的条目得到。
  - 该字段由可选插件 [QQMusic-ID-Injector](https://github.com/apoint123/QQMusic-ID-Injector) 写入（把当前播放 ID 塞进 SMTC 的「流派」）；**未安装时为空**，不影响其余功能。
  - 本地歌曲无法取得 ID（插件已知限制）。

- 线程内自行 `CoInitializeEx(MTA)`（沿用项目既有的 COM 公寓教训）。
- 只做读取，不做任何歌词逻辑；异常一律吞掉并置为「无会话」。

### 4.2 `Lyrics`
把「歌名+歌手」变成 `[(t_seconds, text)]`：

1. 命中本地缓存则直接返回（缓存目录 `%LOCALAPPDATA%/hubmon/lyrics/`，键为 `歌名|歌手` 的哈希）。
2. 否则：`musicu.fcg` 搜索 → 选 `mid` → `GetPlayLyricInfo` → base64 解码 → 解析 LRC。
   - **候选选择**优先精确定位：若快照带 `song_id`（装了 ID-Injector 插件），直接挑 `id` 等于该值的候选，命中即定。
   - 未命中、或没有 `song_id` 时，退回**加权打分**：歌手重合（歌手名出现在候选 `singer` 中）、专辑名重合、时长接近（与 SMTC `duration` 之差），三者加权取最高分；全不重合则取第一条。
3. QQ 接口失败时走第三方 LRC 接口兜底。
4. 每个环节失败都只返回空，不抛异常。

### 4.3 `LyricState`
纯逻辑（可离线单测）：

- 输入：`快照（歌名/歌手/进度/状态）`、`句子表`、`当前配置动效`。
- 输出：`当前句文本`、`上一句文本`、`过渡进度 0..1`、`实际动效名`（轮换时在此裁决）。
- 换歌（歌名/歌手变化）→ 复位过渡状态；无句子表 → 返回「隐藏」。

## 5. 时间轴策略

1. **主策略**：SMTC `position` 直接对 LRC 时间戳定位当前句；`status != playing` → 隐藏整块。
2. **兜底**：若 `position` 不可用（老版本 / 未重启），退化为「换歌时本地单调时钟归零、播放中推进、暂停冻结」估算，效果见 §2 局限说明。
3. 两条策略对外接口一致，`LyricState` 不感知来源差异。

## 6. 渲染与动效

- 位置：单行，顶边 `SPEC_TOP + 4`（≈37），高度约 16px；**水平居中于频谱区** `SPEC_X0..SPEC_X1`。
- 字体：**微软雅黑**（`msyh.ttc`/`msyhbd.ttc`）——现有 FONT_DIR 只含拉丁字体，需新增 CJK 回退链。
- 宽度：按**文字墨框收紧**（不是整条 320），超长用既有 `fit()` 省略号截断；垂直居中沿用 `ink_mid`（项目既定「按字形墨框定位」约定）。
- 半透明：`TEXT` 色 + `alpha = 255 * lyrics_opacity`，叠加 **1px 深色极淡描边**保可读性。
- 绘制时机：`render()` 中 `mode=="spectrum"` 且柱子画完后叠加，仅在启用且有歌词时执行。

### 动效参数（初值，实现期实机微调）

| 动效 | 行为 | 时长 |
|---|---|---|
| `fade` | 旧句 alpha 1→0、新句 0→1 交叉淡化 | 0.35s |
| `geom` | 每字纵向切 3 条窄块，各块从随机散位（±10px 横 / ±6px 纵）缓出归位，alpha 0→1 | 0.5s |
| `rotate` | 每换句在 fade / geom 间交替 | — |

`geom` 的散位由「(行内容, 字序, 块序) 哈希」生成 → 确定性、不闪烁。

## 7. 配置与面板

`config.py` 新增三项（默认关，保持旧行为）：

```
lyrics_enable:  bool  = False
lyrics_effect:  str   = "rotate"   # "fade" | "geom" | "rotate"
lyrics_opacity: float = 0.55       # 0.3 ~ 1.0
```

- 三者均为**绘制期参数，不参与静态烘焙** → **不进 `_look_sig()`**，热更新零重烘焙。
- 面板：在「画面」组内、音频频谱区块之后新增**「歌词」子区块**，出现条件同为 `mode == spectrum`；含开关、动效三选一、透明度滑杆。

## 8. 带宽预算

歌词带叠在频谱顶部（柱子最高、变化最频繁处），其**边际脏区通常较小**（大量像素本就因柱子变化被判脏）。仍需实测约束：

- 用现有 `build/_pool/style_link.py` 实测「8 种风格 × 开歌词」，门限 **700 KiB/s**。
- 超限则按序降级：① 收紧歌词墨框宽度（默认已做）；② 歌词模式设略低 fps 上限；③ 最坏情况限定低成本风格（led/dots/fine）。

## 9. 错误处理

| 情况 | 行为 |
|---|---|
| `winrt` 缺失 / 非 Windows | import 守卫，歌词层静默关闭 |
| 无媒体会话 / 暂停 | 歌词整块隐去 |
| 断网 / 匹配不到 / 接口报错 | 静默不显示歌词层，不阻塞主循环 |
| 线程异常 | 捕获后置「无会话」，下一轮继续 |

## 12. 风险与后续可选增强

- **首次配置摩擦**：用户必须在 QQ 音乐开 SMTC 并**重启**客户端，否则无进度。需在控制面板给出提示文案。
- **seek 失准**：见 §2 局限，无 SMTC 侧解法。
- **匹配精度**：默认用「歌手 + 专辑 + 时长」打分收敛（见 §4.2）；若安装 [QQMusic-ID-Injector](https://github.com/apoint123/QQMusic-ID-Injector)（它把 ID 写进 SMTC 的 genres，形如 `QQ-<id>`），则自动改用精确 ID 定位。**不装插件也能工作，装了更好。**
