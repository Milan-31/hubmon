# 频谱歌词视觉升级 — 设计文档

日期：2026-10-17
状态：待用户审阅
承接：[2026-10-16-qq-lyrics-design.md](2026-10-16-qq-lyrics-design.md)（SMTC 取词 + 时间轴跟唱 + 叠加渲染已实现）

## 1. 目标

在已实现的歌词叠加基础上做**视觉升级**：

1. **艺术文字**：改用更具设计感的中文字体 + 装饰（光晕）。
2. **逐字入场动画**：文字逐字出现，作为**所有动效的默认行为**。
3. **高度错落**：每个字静止高度错落有致，体现设计美感。
4. **面板彩色调节**：控制面板可调歌词文字颜色。
5. **放大显示范围**：字号与歌词带显著增大，让动画看得清。
6. **修复观感缺陷**：现网反馈「文字上方像被砍了一刀」。

## 2. 已确认的决策

| 项 | 决策 |
|---|---|
| 字体候选 | **只保留「幼圆」（`simyou.ttf`）与「细黑」（`STXIHEI.TTF`）**，默认**幼圆** |
| 字号 | **21px**（原 15px），歌词带高 **24px**（原 16px） |
| 逐字入场 | 所有动效默认逐字入场（不是新增第 4 种动效） |
| 入场形态 | **逐字浮入**：淡入 + 从下方轻升到位 |
| 错落 | **确定性随机**垂直偏移 |
| 配色 | **单色取色器**（不做渐变） |
| 装饰 | 光晕（可开关） |
| 其余 | 沿用上一版（跟唱、暂停隐去、断网静默等） |

## 3. 关于「上方被砍一刀」的实测结论

**代码层面没有裁切**。实测（`build/_pool/lyric_clip_probe*.py`）：

- 字形墨框 `getbbox` = `(0,4,120,19)`，`ink_mid` 起点 y=33.5；
- 图层尺寸 20px、粘贴于 y=35，图层 alpha 包围盒 → 帧内 **y 37..52**；
- 同一句用 `ImageDraw.text` 直接绘制（画布充裕）的墨框也是 **y 37..52**；
- 两者**完全一致** → 不存在顶层裁切。

观感上的「砍一刀」来自：**字号太小（15px）+ 半透明压在密集柱形上**，加上横向笔画在小字号下糊成一条平顶。**放大到 21px 后消失**。

**防御性修复（仍然做）**：把 `_lyric_layer` 的图层尺寸从硬编码 `LYRIC_H + 2·PAD` 改为按 `font.getbbox(文本)` + 光晕边距**动态计算**，让任何字号/字体/含超高音符的字都不会被图层边界截断。

## 4. 字体

- 面板「歌词字体」为 `list`，候选：`[["youyuan","幼圆"], ["xihei","细黑"]]`，默认 `youyuan`。
- 映射：`youyuan → simyou.ttf`；`xihei → STXIHEI.TTF`。
- 字体对象按「字体名 + 字号」缓存，面板切换即时生效（绘制期参数）。
- 字体加载失败时回退到 `msyhbd.ttc`，再回退到现有 `F(size,"bold")`。

## 5. 逐字入场（所有动效的默认）

- 第 k 个字（0 基）在换句后延迟 `k × LYRIC_STAGGER` 开始，用 `LYRIC_CHAR` 完成入场。
- 入场 = **alpha 0→1** 同时 **y 由 +3px 升到静止位**。
- 整句过渡时长 `dur = LYRIC_CHAR + LYRIC_STAGGER × (字数-1)`。
- `LyricState` 用该 `dur` 推进归一化的 `t`（0..1），并**把 `dur` 一并返回**，供渲染层换算每字进度：
  `u_k = clamp((t×dur − k×LYRIC_STAGGER) / LYRIC_CHAR, 0, 1)`。
- 动效差异：
  - **渐隐**：逐字 alpha/y 浮入，无碎块（旧句整体淡出）。
  - **几何重构**：逐字浮入 **＋** 每字纵向 3 条窄块从散位飞拢。
  - **轮换**：每次换句在两者间交替。

初值：`LYRIC_STAGGER = 0.045`、`LYRIC_CHAR = 0.22`（12 字约 0.72s），实现期按 21px 实机微调。

## 6. 高度错落

- 每字静止位置在基线上叠加**确定性**垂直偏移，范围 **±3px**（字号放大后同比放大）。
- 偏移由 `crc32(f"{文本}|{字序}")` 映射到 `[-3, +3]`，**不随帧变化、重看不闪**。
- 与逐字入场的初始 y 偏移叠加：入场时从 `静止位 + 3px` 升到 `静止位`。

## 7. 配色与装饰

- 面板「歌词颜色」`color`，默认 `#eef3fb`（暖白）。
- 描边：该色**压暗版**（约 35% 亮度），1px，保对比。
- **光晕**：字形 alpha 蒙版做高斯模糊后染成歌词色，叠在字形下方；面板「歌词光晕」开关，默认**开**。
- 光晕与字形共用一个图层，按「文本 + 字体 + 颜色 + 光晕」缓存，每句只栅格化一次。

## 8. 配置与面板

`config.py` 新增：

```
lyrics_font:  str  = "youyuan"   # "youyuan" | "xihei"
lyrics_color: str  = "#eef3fb"
lyrics_glow:  bool = True
```

面板「歌词」区块在现有三行（显示歌词 / 歌词动效 / 歌词不透明度）之后追加：

```
{"key": "lyrics_font",  "label": "歌词字体", "type": "list",
 "options": [["youyuan", "幼圆"], ["xihei", "细黑"]]},
```

## 9. 几何与成本

- `LYRIC_TOP = SPEC_TOP + 3`（≈36），`LYRIC_H = 24`，带占 `36..60`。
- 带宽：光晕放大脏区，需用 `build/_pool/lyric_budget.py` 重测 8 风格，仍守 **700 KiB/s**；超限则收窄光晕半径或降带高。
- 光晕只在「每句首次栅格化」时计算，逐帧仅做一次按 alpha 的粘贴。

### 9.1 实现期修订（实测驱动，2026-10-17）

实机量得：21px CJK 字体**墨框高 22px**，在 24px 带内垂直居中后，上下各只有 1px 余量；而 `seat ±3`、入场抬升 `+3`、几何重构散位三者可叠加到 ±7px（下）与 ±5px（上），**§10 原定边界 `[SPEC_TOP, SPEC_TOP+28]` 数学上无法容纳**（实测 geom 瞬态最深到 y=64 > 61）。修订如下：

- 新增 `LYRIC_WIN_TOP = SPEC_TOP - 1`、`LYRIC_WIN_BOT = SPEC_TOP + 34`：这是**允许窗口**（静止带 + 入场/散位余量），实测三种动效全程 `y ∈ [35, 64]`，落在窗口内。
- `_jitter` 的**纵向**散位由 ±4 收窄到 **±2**（横向仍 ±10），避免单字散位把墨迹顶出窗口。
- 新增 `_paste_overlay()`：每次粘贴都按窗口裁剪，**任何字形/字体/光晕都不会越窗**（几何保证，而非仅靠参数凑）。
- §10 的越界断言改用 `R.LYRIC_WIN_TOP/BOT` 常量，并把采样从 4 个 t 扩到 **t=0.00..1.00 全扫（步长 0.01）**，因为峰值出现在过渡中段而非采样点。

### 9.2 实现期修订二：几何重构改为全屏破碎（2026-10-17）

实机反馈「几何重构貌似失效」。实测定位根因：逐字进度 `u` **同时**驱动 alpha 与散位 —— 散位最大时 alpha≈0，碎片几乎不可见；证据是几何重构的绘制范围 `x=[72,243]` 与纯渐隐 `x=[75,243]` **只差 3px**，等于没动。修订：

- **恢复可见性**：几何重构的碎片改走 **alpha 地板** `LYRIC_GEOM_FLOOR = 0.6`，即 `a = base·(FLOOR + (1-FLOOR)·u)`，散开时仍有六成不透明，动势才读得出来（旧实现同样有 0.30 地板，逐字改造时丢了）。
- **全屏破碎**：`_jitter` 换成 `_shatter(txt, k, bi, x, y)`，碎片起点改为**哈希选中的屏幕任意点**（`x∈[0,320)`、`y∈[0,170)`），以「相对静置位的偏移」表达，保证每片都从屏内起飞而不是一半被裁在画面外。
- **两处豁免**：几何重构的碎片粘贴**不再**走 `_paste_overlay` 的越窗裁剪（全屏飞行）且**不再画旧句**（整句垫在碎片后面只会糊掉破碎感）。`LYRIC_WIN_TOP/BOT` 现在只约束「静止态」：定稿行与渐隐入场。
- **实测**：三种动效全程 `y∈[33,169] x∈[1,319]`（几何重构占满全屏），渐隐/轮换仍在 `[32,67]` 窗内；越界断言按动效分别取边界（geom 取整屏，其余取窗）。
- **带宽**：8 风格 × 开歌词 × 开光晕 重测，最差由 571.4 升到 **597.5 KiB/s**，仍守 700 门限。

### 9.3 实现期修订三：几何重构改为缓慢、流畅的非线性节奏（2026-10-17）

用户要求「将这个动画做成缓慢且流畅的非线性节奏动画」。两处改动：

- **放慢**：新增 `LYRIC_GEOM_SLOW = 1.5`，几何重构的整句时长拉伸 1.5×（`dur = (CHAR + STAGGER·(n-1)) · 1.5`）。
  ⚠️ 关键坑：**只拉伸 `dur` 是无效的**。因为 `t` 按 `dt/dur` 推进、而 `u = (t·dur − k·STAGGER)/CHAR`，`t·dur` 恒等于真实经过时间，`dur` 会约掉 —— 只拉伸 `dur` 只会在「揭示已经放完」之后空等，不会放慢动作。因此 `word_u` 增加 `slow` 参数，把 `STAGGER` 与 `CHAR` 一并按同一系数拉伸，两处必须配对使用。
- **非线性**：几何重构的位移与透明度改走 **smoothstep**（`p = u²(3−2u)`）而不是渐隐的衰减曲线 —— 起步从容、中段悬停、末段平滑滑入，这才是「缓慢流畅」的观感来源（旧曲线 `(1−u)²` 在中段只剩 25% 位移，碎片早已贴回原位）。
- **顺带修**：`word_u` 在 `t = 1` 处的除法会差 1 ULP（实测 `0.9999999999999998`），导致「已定稿」帧差一点点；改为 `t ≥ 1` 直接返回精确 `1.0`。
- **带宽**：1.5× 时长使过渡期占用更久，最差升至 **608.9 KiB/s**，仍守 700 门限；实机 50–58fps。

## 10. 测试点（沿用 `build/_pool/` 断言惯例）

| 脚本 | 覆盖 |
|---|---|
| `lyric_font.py` | 两种字体可加载、映射正确、回退链成立；面板 schema 含三项新键且选项正确 |
| `lyric_word.py` | 逐字进度换算：`u_k` 随 k 递减起始、单调、t=1 时全为 1（且精确等于 1）；`dur` 随字数变化；geom 的 `dur` 恰为 1.5×，且慢节奏由 `word_u` 的 `slow` 承担（同一 t 下更靠后） |
| `lyric_jitter.py` | 错落偏移确定性（同输入同输出）、落在 ±3、不随帧变化 |
| `lyric_render.py`（扩展） | 21px 下动效越界按动效分别判定（geom 取整屏、其余取窗 `[LYRIC_WIN_TOP, LYRIC_WIN_BOT]`，全 t 扫描）；geom 碎片起始跨度 > 半屏（防退化回「3px 挪动」）；渐隐/轮换 t 增大覆盖率不减；`visible=False` 与基线逐像素相同；出预览图 |
| `lyric_glow.py` | 光晕开关生效（开/关帧不同）；光晕不越出窗口 |
| `lyric_budget.py`（扩展） | 8 风格 × 开歌词 × 开光晕 的带宽 ≤700 |

## 11. 风险

- **21px 字高**使歌词带占频谱顶部约 1/5，柱形可视高度减少；可接受（用户明确要求放大）。
- **细黑**笔画细，压在亮柱上对比度低于幼圆；已有描边 + 光晕兜底，实现期用预览图复核。
- 逐字入场使整句过渡变长（约 0.7s），极短句会更快、极长句更慢；`dur` 随字数自适应，不会「卡住」。
