# 音频频谱模式 · 第二轮迭代 设计文档

> 状态：**方向已获用户批准**（"按这个方案来，直接开始构建"）
> 日期：2026-10-15
> 关联：第一轮见 `2026-10-14-audio-spectrum-mode-design.md`（那份是底座，本份只写这一轮的增量）
> 用户原话：「采集设备采用选取器而不是手动填写；适当提高灵敏度的缓冲，现在效果比较抖；适当调整频谱宽度，提高整体频谱利用率，现在低频经常是满的，高频没怎么利用到；去除镜像渐变柱，加入更多其他的风格，如折线一类的风格，保证有6-8种不同的风格」

---

## 0. 本轮改什么

| 项 | 决定 |
|---|---|
| 采集设备 | 面板改成**选取器**（下拉），服务端枚举输出端点；保留「跟随系统默认」 |
| 灵敏度 | 包络放缓 **ATTACK 0.05→0.09 / RELEASE 0.25→0.38**，并给一个面板可调滑条 |
| 频段利用 | 每段加**倾斜增益**（围绕 1kHz ±3dB/oct，粉红噪声补偿）—— 这才是"低频满、高频空"的根因；频带范围保持 40Hz–16kHz |
| 柱宽 | 窄柱风格的柱宽 **8px → 10px**（与 LED 格同宽），把 12.667px 的 pitch 填得更满 |
| 风格集 | **8 种**（见 §3）；**删除 mirror**；旧配置 `mirror` 自动迁移回 `led` |
| 刷新率 | 不动（沿用 60fps 目标 + 局部刷新） |

## 1. 采集设备选取器

**为什么不是文本输入**：第一轮踩过的坑是"默认播放设备在多虚拟端点声卡上不可靠"（本机默认是 SteelSeries Sonar 的 Gaming 端点，而音乐走 Chat）。手填设备名要求用户知道内部名字，等于把这个坑留给用户。改成从枚举结果里挑。

**接口**：新增 `GET /api/spectrum-devices`，返回

```json
{"follow": "跟随系统默认", "devices": ["扬声器 (TOPPING USB DAC)", ...]}
```

**必须在自己线程里先起 COM 公寓** —— 与第一轮打包时踩的 `CO_E_NOTINITIALIZED` 同源：`webui` 的 HTTP handler 跑在独立线程，`soundcard` 的 `_com` 单例只覆盖"导入它的那个线程"，冻结包里这一侧枚举设备会当场复现那个错误。处理方式：handler 里先调 `audio._com_apartment()`（直接复用），再用 **`all_speakers()`** 枚举 —— 它天然只列**输出**端点，正好全是可挂回环的，顺带避开麦克风（本机回环列表里混着 2 个麦克风，且它们重名）。

**存储与匹配**：仍然按**名字**存取（沿用现有 `Spectrum._open()` 的匹配逻辑），面板显示可读名而不是 GUID。两个边界：

- 枚举失败（无 soundcard / COM 起不来）→ 返回空列表，面板退化为「跟随系统默认」+ 当前值，不报错不崩。
- 当前配置值不在枚举结果里（设备被拔了，或枚举失败）→ 把当前值**作为附加项注入**下拉，避免用户的选择在界面上凭空消失。

**面板控件**：新增行类型 `list`（原生 `<select>`）。顺带把「频谱风格」也换成 `list` —— 8 个选项用分段按钮会溢出。

## 2. 分析层重调（抖动 + 频段利用）

**根因**：现在 24 段**带内峰值** + **线性 dB 映射（−60dB 底）**。音乐能量约 −3dB/oct 递减，跨 8.6 个八度就是 ~26dB 落差，于是低频常年贴顶（level≈1）、高频趴在 0.1 以下。抖动则来自 0.05s 的快攻击 + 0.25s 的释放：单帧瞬态一闪一闪。

- **倾斜增益**：`gain_db[i] = TILT × log2(fc_i / 1000)`，`fc_i` 是每段几何中心。默认 `TILT = +3.0 dB/oct`：40Hz 处 −13.9dB、16kHz 处 +12.0dB，跨约 26dB，正好把"低频满/高频空"拉平。频段范围**保持 40Hz–16kHz**（往上扩到 18-20kHz 只会把段浪费在近乎静音的内容上，反而降利用率）。
- **包络放缓**：`ATTACK 0.09s / RELEASE 0.38s`。
- **两个面板滑条**（都进 `Config`、都**不进** `_look_sig()`，属动态参数）：
  - `spectrum_smoothing` 0..1：0 = 快（0.05/0.25），1 = 慢（0.16/0.60），默认对应 0.09/0.38。
  - `spectrum_tilt` −6..+6 dB/oct，默认 +3.0。
- **保持带内峰值聚合**（不改分位数）：第一轮 spec 明确选了峰值"瞬态更跟手"，倾斜增益已经解决饱和问题；先不动聚合方式，若要再谈。
- **柱宽 8px → 10px**：窄柱风格（peak / 新增的细柱等）由 `SPEC_BAR=10` 复用到 LED 格宽，屏幕利用率从 63% 提到 79%。

**可观测性**：把 `spectrum_bands` 加进面板 `/api/stats` 的 provider —— 这样频段利用率可以**客观量出来**，不用再碰用户的音频通道（第一轮为此放过合成音源，已被明确要求停手）。

## 3. 风格集（8 种）

保留两种已认可的、删掉一种、新增六种。**每种风格必须先量带宽再收**。原定硬预算门是 **≤450 KiB/s**，但实测发现这条门限与设计自己的表格冲突——已发布的 `peak` 实测 686 KiB/s、现场却能跑到 48–50fps，被删的 `mirror` 才是真正过不了的那条（≈1000 KiB/s）。因此门限改设 **≤700 KiB/s**：它正好把 mirror 挡在外面，而不是误伤已经在用的风格。第一轮删掉 mirror 就是因为没设这道门。

| 键 | 风格 | 形态 | 每帧成本预判 |
|---|---|---|---|
| `led` | LED 点阵柱（默认） | 10px 方块矩阵，亮/灭 + 幽灵底 | 低（12 KB，已实测） |
| `peak` | 峰值保持 | 平色柱 + 3px 亮帽，>0.88 转琥珀 | 低（22 KB，已实测） |
| `line` | 折线波形 | 24 点细折线（~2px），不填充 | 中（每段只跨 1 行，≈6–15 KB 估） |
| `area` | 面积山形 | 折线 + 下方填充渐变的**上沿** | 中低（填充内部稳定） |
| `sym` | 对称镜像柱 | 中线上下对称的**平色**柱 + 圆头亮帽 | 低（保留 mirror 的几何，去掉那根随高度缩放的渐变条） |
| `grad` | 单侧渐变柱 | 自基线向上、按**绝对高度**取色的渐变柱 | 低（位置稳定 ⇒ 只脏跨过的行） |
| `dots` | 圆点脉冲 | 圆点矩阵，点径随电平脉冲 | 低 |
| `fine` | 细柱阵列 | 细柱 + 开阔间距，柱顶 1px 亮头 | 低 |
| ~~`mirror`~~ | ~~镜像渐变柱~~ | **删除**（整柱随高度缩放 ⇒ 整列重画，最坏 ~1 MiB/s） | —— |

**烘焙与动态的分工**（沿用第一轮）：每种的幽灵格 / dB 网格 / 中线 / 导轨 / 刻度进静态层；只有柱体、折线、填充的上沿逐帧画。风格分发改成**注册表**（`STYLE_CHROME` / `STYLE_BARS` 两张表），新增风格不再改 `if/elif` 链。

**配置迁移**：`mirror` → `led`（加载时映射，不报错）。`panel_spec.py` 的选项序列断言、`spec_mirror.py` 一并更新/删除。

## 4. 明确不做（YAGNI）

- 不做瀑布谱（滚动热图 ≈ 整带每帧重画，必超预算）、不做环形/雷达谱。
- 不做麦克风输入、不做多设备混音、不做与系统音量联动。
- 不改频段聚合方式（先靠倾斜增益），不改仪表盘卡片与壳体（那是工作流 B）。
- 不再用合成音源占用用户音频通道 —— 一律用用户自己的音乐 + `/api/stats` 的 `spectrum_bands` 客观验证。

## 5. 验证清单

1. `python -m compileall -q hubmon` + 全部 `build/_pool/spec_*.py` 断言绿（含每个新风格）。
2. `style_link.py` 逐风格量脏区，**逐个过硬预算门**（≤700 KiB/s 折算）。
3. `style_cost.py` 逐风格量渲染耗时（预算 16.7ms）。
4. 冻结 exe 上验证**选取器枚举**（COM 修复必须在 exe 上复测，源码通过不算数）。
5. 实机用**用户自己的音乐**跑：读 `/api/stats` 的 `spectrum_bands` 确认低频不再贴顶、高频不再趴底；`kb_s` 与 fps 达标。
6. 旧配置含 `"mirror"` 时能正常启动并回落到 `led`。

## 6. 实测结果（2026-10-15）

**渲染耗时**（`style_cost.py`，`Demo` 满幅驱动，优于 16.7ms 预算很多）：led 1.3、peak 1.0、line 0.8、area 2.4、sym 0.9、grad 2.5、dots 1.1、fine 1.0 ms/帧；quartz 同量级。最差为 `grad` 2.5ms。

**链路成本**（`style_link.py`，30fps 折算，预算 700 KiB/s）：

| 风格 | KiB/s | 风格 | KiB/s |
|---|---|---|---|
| led | 370 | sym | 649 |
| peak | 686 | grad | 403 |
| line | 519 | dots | 304 |
| area | 539 | fine | 380 |

最差为既有 `peak` 686，仍在门限内；被删的 mirror（≈1000）确实过不了。

**实机（冻结 exe + 用户自己的音乐）**：8 种风格逐一切换，`spec_state` 全程 `ok`、`connected`、`bands=24`；fps 47–59（line/area 因横跨全宽的图元略低，仍 >30）；`kb_s` 141–572。

**利用率**（8 次采样 24 段）：无任何段贴顶（最大 0.73，此前低频常年 1.0）；>0.1 的段达 20 个。低频段 0–3 落在 0.01–0.11 —— 对该曲目而言 3 dB/oct 的倾斜偏强，低频反而偏空；面板的「频段倾斜」滑条可下调（属动态参数，不触发重烘焙）。

**冻结 exe 选取器**：`GET /api/spectrum-devices` 返回 9 个输出端点，本机配置的 `扬声器 (TOPPING USB DAC)` 在列 —— 证明 handler 线程里的 COM 公寓修复在冻结包里也生效。
