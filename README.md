# hubmon

把电脑的实时状态投到带屏 USB 集线器的小屏幕上 —— 一个精致、常驻后台的桌面监测仪表盘。

hubmon 在本机后台采样硬件状态，渲染成一帧 320×170 的画面后推送到 Hub 的屏幕上，
并附带一个本地网页控制面板：所有外观与推流选项都能实时调整，改完立即生效、无需重启。

> 已在 **佳点 V1PRO** 带屏集线器（320×170 横屏）上实机验证：约 50–58 fps，占用带宽约 150–600 KiB/s
> （随画面内容与歌词动效波动；USB Full-Speed 链路本身约 800 KiB/s 上限）。

## 特性

### 两种显示模式

- **指标仪表盘**：CPU / GPU / 内存 / 整机功率四张大卡片，数值带滚动动效与指数平滑插值，读数不跳变。
- **音频频谱**：实时采集系统播放的声音（WASAPI 回环），渲染成 **48 段**频谱；8 种风格任选 ——
  LED 点阵柱、峰值保持、折线波形、面积山形、对称镜像柱、单侧渐变柱、圆点脉冲、细柱阵列。
  可指定采集设备、频段倾斜（围绕 1 kHz 的 dB/oct 增益）与灵敏度平滑。

### 在频谱上跟唱

- **歌词叠加**：频谱模式下自动取当前播放歌曲的歌词，叠加在频谱上部半透明显示，按时间轴逐句跟唱；
  暂停或无歌曲时整块隐去，断网或匹配不到歌词时安静不显示。
- **三种动效**：**渐隐**（逐字浮入）、**几何重构**（每字拆成竖块，从屏幕任意位置缓慢飞拢归位）、
  **轮换**（每次换句在两者间交替）。
- **艺术字体**：幼圆 / 细黑二选一，21px 字号，逐字入场；带**确定性高度错落**（由文本与字序哈希决定，重看不闪）——**中文逐字错落**，**英文按单词整体错落**（词内字母保持水平，一个单词不再逐字母抖动）。
- **自动换行**：一行放不下时**按空格断句自动换两行**（中文按字换行），保证整句歌词完整显示，不再用省略号截断；两行共用一次逐字入场，逐字从左到右打完第一行再打第二行。
- **可调配色**：歌词单色取色器 + 光晕开关，描边自动取该色的压暗版。
- **取词链路**：Windows 媒体会话（SMTC）读歌名 / 歌手 / 专辑 / 进度，QQ 音乐接口取带时间轴歌词，
  第三方（网易云）LRC 兜底，结果按曲目缓存。详见「音频频谱与歌词」。

### 画面

- **水池式占用**：CPU / GPU / 内存卡片按占用比例注水，带行进涌浪、慢速起伏与随负载倾斜的动效，水面与卡片边缘均做抗锯齿；石英机芯风格下水位裁切在表圈之内，读作表壳里的液位视窗。
- **型号识别**：自动从 CPU / 显卡名称中提取型号（如 `i5-12400F`、`RTX 5060`）显示在读数正下方；CPU 卡片右上角显示核心·线程数（如 `8C·16T`）。
- **顶栏信息**：左侧为**主板型号**（如 `Z690M Snow Dream`，读不到时回退主机名）、实时上下行网速、右侧当前时钟（可切 12/24 小时制与是否显示秒）、一盏电源指示灯。
- **GPU 温度**：10 秒刷新一次（CPU 温度不采集，原因见「数据来源」）。
- **自定义背景**：三种来源。**自动**——设过图片就用图片，否则用渐变；**纯渐变**——纵向三段颜色各自由面板取色盘挑选（另有四套配色预设一键套用）；**图片**——点击「选择图片」从资源管理器挑一张图，模糊度与亮度可调，面板内置**取景框**，拖动平移、滑条缩放，所见即所得；使用图片时卡片改为**全透明无边框**，整屏读作一张连续的画面。
- **双界面风格**：面板可一键切换，两套观感差异明显。**玻璃拟态**（默认）——圆角玻璃卡片，内部透出背景模糊与高光，读数为矢量字滚动；**石英机芯**——直角金属表壳：镀铬表圈由亮到暗压出斜面，四个边角各一颗一字螺钉，表盘是枪灰金属底，顶栏是一块同样的金属铭牌（绿点脉冲即面板电源灯），读数改为七段石英电子表数码，未点亮的笔画以暗色常显（这是真表盘的读法，也更易辨识），换数时旧笔画淡出、新笔画淡入。
- **纯数据动效**：画面上的动态只来自数据本身——水池液面、数字滚动、负载告警环；背景与卡片没有任何装饰性动画。
- **本地控制面板**：单页界面、五组页面，实时热更新，含「退出程序」按钮；页头显示当前连接的 USB 集线器厂家信息与版本号。
- **单文件可执行**：PyInstaller 打包，后台运行、无控制台窗口、无任务栏残留。

## 硬件与系统要求

| 项目 | 要求 |
| --- | --- |
| 屏幕 | 带可编程小屏的 USB Hub（320×170 横屏），已在佳点 V1PRO 验证 |
| 系统 | Windows 10 / 11（依赖 Windows 性能计数器与 `nvidia-smi`） |
| CPU | `psutil` 可读即可；CPU 频率依赖 Windows PDH 性能计数器 |
| 显卡 | NVIDIA 显卡可选；没有时 GPU 相关读数留空，其余指标正常 |
| 音频频谱 | Windows WASAPI 回环采集（`soundcard`），仅 Windows |
| 歌词 | 需要 `winrt` 模块化包，且播放器要向 SMTC 上报媒体信息（见下） |
| Python | 3.10 及以上（从源码运行时） |

## 从源码运行

```powershell
git clone https://github.com/<你的用户名>/hubmon.git
cd hubmon

python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python run.py
```

首次运行前请先关闭厂商标配的控制工具（它会独占设备）；确实需要同时运行时可加 `--force`。

### 命令行参数

| 参数 | 说明 |
| --- | --- |
| `--fps N` | 覆盖帧率上限，`0` 表示不限速（默认读取配置） |
| `--demo` | 使用合成数据，无需真实硬件（也会灌入循环假歌词，便于预览叠加效果） |
| `--full` | 始终发送整帧（关闭局部更新） |
| `--preview DIR` | 只渲染 PNG 预览到目录，不连接设备 |
| `--frames N` | 预览模式生成的帧数（默认 120） |
| `--port N` | 指定控制面板端口 |
| `--no-browser` | 启动时不自动打开浏览器 |
| `--force` | 即使厂商工具在运行也强制推流 |

### 无需设备预览效果

```powershell
python run.py --preview out --demo
```

会在 `out/` 下生成若干放大后的 PNG，用来检查配色与布局。

### 快捷启动

- `hubmon.bat` —— 双击即从源码启动（`python -m hubmon.main`），退出后窗口保留，方便看报错。
- `打开控制面板.bat` —— 双击打开控制面板；若监测器尚未运行会**先自动启动**（优先用 `dist\hubmon.exe`，
  没有则回退 `pythonw`），最多等约 30 秒再打开浏览器。端口若不是默认 8756，改脚本顶部的 `PORT`。

## 控制面板

程序启动后会自动打开 `http://127.0.0.1:8756/`（端口被占用时自动顺延）。
页头固定显示当前连接的集线器厂家信息与版本号，以及 CPU / GPU / 内存 / 功率 / 推流帧率等实时指标；
左侧五组页面，仅右侧内容区滚动：

- **主题**：「风格与配色」—— 界面风格（玻璃拟态 / 石英电子）、配色方案预设、四项指标强调色。
- **画面**：「显示模式」指标仪表盘 / 音频频谱；**音频频谱**（选频谱模式才出现）—— 频谱风格、采集设备、频段倾斜、灵敏度平滑；**歌词**（同前）—— 显示开关、动效、不透明度、字体、颜色、光晕；「显示调节」亮度 / 饱和度 / 玻璃质感 / 背景亮度；「指标显隐」内存 / 功率 / 帧率 / 卡片内瓦数；「屏幕顶栏」左上角内容 / 24 小时制 / 显示秒 / 网速。
- **背景**：「来源」自动 / 纯渐变 / 图片；「渐变」三段颜色取色；「图片」选图、模糊度、亮度，另有面板内置取景框（拖动平移、滑条缩放）。
- **动效与推流**：「推流」帧率上限、局部更新、数值刷新间隔、帧率刷新间隔；「文字动效」数值滚动开关与速度。
- **系统**：面板端口、启动时是否打开浏览器、PresentMon 路径。

> 取景框只有在设置了图片之后才出现；「选择图片」会弹出 Windows 的文件选择对话框。
> 饱和度与玻璃质感只作用于玻璃拟态风格；石英电子风格用的是新拟物阴影，改用亮度 / 背景亮度调节。

改动即时生效：界面风格、背景图片、频谱与歌词等绘制期参数选完就应用到屏幕并被记住；
其余项点「保存设置」后一并应用到屏幕并写入配置文件，下次启动继续生效。

## 音频频谱与歌词

### 频谱采集

- 频谱走 WASAPI **回环**采集，采集的是「某个输出端点正在播放的声音」，不是麦克风。
- **采集设备**在面板里用下拉选取（保留「跟随系统默认」一项），选中后会被实时打开验证有效性。
- ⚠️ **最容易踩的坑**：如果你的机器上有 SteelSeries Sonar、Voicemeeter 一类的虚拟声卡，
  「系统默认播放设备」往往**不是**你实际听到声音的那个端点（声音可能在 Sonar 的 Chat 通道里，
  再混音到物理输出）。此时采集会一直静默——链路正常、状态显示 ok、但柱子不动，极易误判为程序坏了。
  正确做法：把「采集设备」指向**你实际听到声音的物理输出**（例如 `扬声器 (TOPPING USB DAC)`），换输出设备时同步改。
- 默认启用围绕 1 kHz 的频段倾斜（±dB/oct，即粉红噪声补偿），解决低频满幅、高频利用率不足；
  「频段倾斜」与「灵敏度平滑」两个参数可实时调。

### 歌词取词

- 通过 Windows 媒体会话（SMTC）读取当前曲目的歌名 / 歌手 / 专辑 / 播放状态与播放进度，
  再用 QQ 音乐接口取**带时间轴**的歌词（Base64 LRC），QQ 那边没有时回退到网易云公开接口；
  取到的歌词按曲目缓存到 `%LOCALAPPDATA%\hubmon\lyrics`，重听不必再联网。
- **匹配要有正证据**：歌词候选必须与当前会话的歌名相符、或歌手与时长同时吻合，才算命中；无法确证时**宁可不显示**，
  也不会盲选搜索的第一条 —— 否则浏览器在放视频时会把网页标题当歌名，屏幕上冒出一首根本没在播的歌。
- **同时播放多个音源**：QQ 音乐与浏览器等**同时发声**时，系统会把「当前媒体会话」判给最近活跃的那个（往往正是浏览器，
  其标题是网页名而非歌名）。hubmon 会枚举**所有**媒体会话，在正在播放的会话里按「注入的 QQ 歌曲 ID > 有歌手 > 有标题」
  挑选，优先取到真正在放歌的那一个；没有任何会话在播放时才退回当前会话。
- **前置条件**：播放器必须开启向 SMTC 上报（QQ 音乐在「设置 → 桌面歌词 / 媒体控制」一类开关里），
  且**改完要完全重启播放器客户端**才生效。否则只会拿到歌名、拿不到播放进度。
- **进度精度**：能拿到 SMTC 时间轴的播放器（如大部分支持 Windows 媒体控制的播放器）逐句精确跟唱；
  QQ 音乐不提供时间轴，会**降级为本地时钟估算**，此时手动拖动进度条会短暂失准。
- **可选提升匹配准确度**：安装 [QQMusic-ID-Injector](https://github.com/apoint123/QQMusic-ID-Injector)
  之类的插件，把精确歌曲 ID 注入 SMTC，歌词匹配会从「模糊打分」变成「精确命中」。
- 不影响主程序：缺失 `winrt` 包、非 Windows 环境、断网或匹配不到歌词时，歌词功能**静默关闭**，其余功能照常。

## 配置

配置保存在 `%APPDATA%\hubmon\config.json`，字段与面板一一对应，可直接编辑。
命令行传入的参数只对本次运行生效，不会写回文件。

## 设备接入与厂家接口

`docs/vendor-api/` 原样收录了厂家提供的两份接口文档，作为后续开发的基础：

- `v1pro-developer-api.md` —— 开发者 API 文档：本地 HTTP 服务、USB 使用权移交、底层 USB 函数与型号兼容范围。
- `v1pro-local-api.openapi.json` —— OpenAPI 3.0 描述文件，可直接导入 Postman / Apifox 等工具。

要点：

- 厂商标配 GUI 在本机 `http://127.0.0.1:8765` 提供 HTTP 服务（`POST /live` 提交实时文字、`GET|POST /usb/status` 查询设备状态）。
- `POST /usb/handoff/{start,keepalive,finish}` 提供 USB 使用权租约：拿到租约后可以合法地接管设备，**不必强杀厂商进程**。
- 型号以设备返回的信息为准（V1 / V1PRO / V2 的端点与画面尺寸各不相同），文档同时公开了 RGB565 大端格式与 LIVE 协议。
- 文档引用的 `v1pro-usb-protocol.md`、`v1pro-compressed-transfer.md`、`gfm3-persistent-lz4.md` 本次未提供。

hubmon 目前仍采用直连 USB 推流的方式；若厂商 GUI 正在运行，请先退出，后续可考虑接入上面的租约接口。

## 数据来源

| 指标 | 来源 |
| --- | --- |
| CPU 占用 / 频率 | `psutil` + Windows PDH 性能计数器（`% Processor Performance` × 基准频率） |
| CPU 核心 / 线程 | `psutil.cpu_count()` |
| 内存 | `psutil` |
| GPU 占用 / 频率 / 功耗 / 温度 / 显存 | `nvidia-smi` |
| 网速 | `psutil` 网卡计数器，1 秒滑动窗口 |
| 前台窗口帧率 | [PresentMon](https://github.com/GameTechDev/PresentMon)（可选） |
| 整机功率 | CPU 占用估算 + GPU 实测功耗 + 平台基线功耗，属**估算值** |
| 主板型号 | 注册表 BIOS 信息（读不到时回退主机名） |
| 音频频谱 | `soundcard` WASAPI 回环采集 |
| 歌曲信息 / 进度 | Windows 媒体会话（SMTC，`winrt` 模块化包） |

CPU 温度不在此列：纯用户态下读不到核心温度，回退到主板 ACPI 热区的读数既不准也不稳定，
需要 LibreHardwareMonitor 之类的工具在后台常驻才有意义，所以不再采集。

## 打包为单文件 exe

```powershell
pip install pyinstaller
python build.py
```

输出 `dist/hubmon.exe`：单文件、无控制台窗口，双击即用。
本机若存在 PresentMon 会被一并打包，否则该功能留空。

## 项目结构

```
run.py              入口（供 python 直接运行与 PyInstaller 使用）
build.py            打包脚本
requirements.txt    运行依赖
hubmon.bat          从源码启动的快捷方式
打开控制面板.bat     打开控制面板（未运行时先自动启动）
assets/             应用图标（.ico / .svg 与生成脚本）
docs/
  vendor-api/       厂家提供的接口文档（原样收录）
  superpowers/      设计说明与实现计划
hubmon/
  main.py           主循环、命令行解析、增量更新调度
  sensors.py        后台采样线程（CPU / GPU / 内存 / 网速 / 帧率）
  audio.py          音频回环采集与 48 段频谱分析
  lyrics.py         歌词取词（SMTC + QQ 音乐 / 网易云）与逐句跟唱状态机
  render.py         画面渲染与位图转换
  transport.py      屏幕输出
  webui.py          本地网页控制面板
  config.py         配置定义与 JSON 持久化
```
